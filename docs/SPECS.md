# Video Maker: specifications

Living specification of the Video Maker. Update it for structural changes only (modules, settings, flow, stack, CI/CD).

## Flow

Makes one-minute marketing films of Wavestone AI platforms from a GitHub repository, in one to three languages (`en-US`, `fr-FR`, `de-DE`), one MP4 per language.

1. **Source.** The page has no server: everything below runs in the browser (`js/videomaker/api.js` answers the page with real `Response` objects). `analyze` reads a GitHub repository with the GitHub REST API called from the page (metadata, README, bounded file tree, a few product-describing files) and lists candidate pictures (README images, screenshot-like files). An optional GitHub token is typed per session and never stored. Pictures are fetched by `image` (GitHub hosts only, bytes sniffed as PNG/JPEG/WebP/GIF, 8 MB cap) so the canvas stays exportable. The author can also upload or paste screenshots. An animated GIF (README ones included) or a short video clip (MP4 or WebM, 8 MB at most, three animated pictures per project) can stand in for a screenshot: `clips.js` samples it once in the browser into at most 6 seconds at 10 frames per second (the first 6 seconds by default; the Start and Length fields on the picture's card cut another window out of the original file, which the project keeps as base64 for that purpose, up to 8 MB per clip) (GIF through `ImageDecoder`, video through a `<video>` element fed by a blob: URL, which the page's CSP allows with `media-src blob:`), keeps the first frame as the still picture and the sampled frames as JPEGs in the saved project, and plays the clip in a loop from the start of the scene that shows it, in the preview and in the MP4 export alike (the frame is picked from the scene time, so the export stays deterministic). A GIF the browser cannot animate falls back to its first frame. The author can paste any text and add documents, all read in the browser: PPTX and DOCX files with no library (slide text with speaker notes, document paragraphs; their larger embedded pictures join the screenshots), PDF files with the vendored pdf.js (`js/vendor/pdfjs`, 10 MB, 200 pages, text only, no OCR). The extracted text lands in the editable text box (80,000 characters at most) and is sent with the repository material, which is trimmed first to keep the request under its 150,000-character limit. Reading a web page by address and capturing a URL need a server and do not exist in this version: the author pastes the text or a screenshot.
2. **Script.** `script` (an NDJSON stream of progress lines, then the result, built in the page) sends the source material (repository and/or the author's text and documents), the brief (product name and URL, audience, tone, target duration, the author's key strengths, which must all appear) and up to six downscaled screenshots to the AI provider the author set in the AI settings (see *AI settings* below), with the author's own key, straight from the browser. Claude (`claude-opus-5-5` by default, streamed with adaptive thinking), OpenAI, OpenRouter and any OpenAI-compatible local server are supported; a local server gets the pictures named, not sent. A purpose selector picks the story, register and default audience and tone of the prompt: *product pitch* (the default marketing film), *proposal summary* (the executive summary of a commercial proposal dropped as a PDF, PowerPoint or Word file: the client's need, our approach and its key points, the planning, our strengths and differentiators, the team; an "End with the price" option adds a closing key-figures scene with the price exactly as the proposal states it, and without it prices, fees and budgets are kept out of the film), *project presentation* (stakes, goals, approach, results, next steps), *crisis exercise debrief* (scenario, key moments, strengths, areas to improve, action plan; factual and blame-free, no individual named), *trade show* (an invitation film before an event: the event, what we will announce, what we will show on the stand, where to find us with venue, hall, stand and dates, and the team on site) or *no particular angle* (structure and tone taken from the supplied text, no marketing spin). Outside the product pitch, the prompt requires every attached picture to be shown, and the normaliser puts the first one in the opening hook when the film uses none. A rhythm selector (fast by default for the product pitch, standard for the other purposes) sets the cut: *fast* asks for more, shorter scenes (about one every four to five seconds, 16 at most) with one short spoken line each (3 to 14 words) and on-screen titles of one to four words, at about 1.7 narration words per second, and the timeline shortens its minimum scene lengths, pauses and transitions accordingly; the rhythm can be changed again in the script editor. Target lengths go from 30 seconds to 1 min 30, and the requested number of scenes follows the length. A "Marketing ++" option, for the product pitch only, asks for a bolder, benefit-first voice with punchlines on screen, without relaxing the sourcing rules. The prompt adapts gitdiagram's explainer approach to marketing: one story from a hook to a closing line, then a call to action, with on-screen items appearing on cue words. Repository text is fenced as untrusted data. The model returns scenes with a type (`hook`, `problem`, `reveal`, `screenshot`, `features`, `steps`, `stats`, `quote`, `team`, `planning`, `cta`; `team` shows two to six people named in the material as portraits with initials, name and role; `planning` is a Gantt chart of two to five phases whose bars grow on their cue words, on a true week or month scale when the periods are numbered, "W1-W4" or "M1-M3", and evenly cascaded otherwise), a layout variant, a picture with a focus region and callout points, icons, and per-language copy (narration, on-screen text, cue words). The server bounds and normalises it and retries once with the validation error. One scene structure is shared by all languages.
3. **Look.** Four visual styles render the same project (the continuous *Produit* style is the default): *Slides* (successive Wavestone scenes, brand-gradient hooks and closings), *Produit* (one continuous white canvas the camera travels across, gitdiagram-like, with a cursor clicking through the screenshots) *Showcase* (an Apple-style app film, vertical 1080×1920 by default and switchable to 16:9: huge condensed capitals with a green eyebrow naming the moment, drifting indigo colour blooms, the product's screens rising in a phone or browser frame and zooming through to the interface with taps on the callout points, counters, and whip cuts with motion blur; choosing it asks the model for moment-by-moment, punchline copy) and *Launch* (a dark, cinematic launch teaser: keycaps and an app-icon reveal, glowing indigo glass windows on an endless canvas, the narration typed into a command bar, screenshots on white cards wired to the windows, a zoom-out, a white flash and the logo). *Launch* keeps on-screen text to short titles, and choosing it in the brief asks the model for a shorter, lighter script (about 1.6 narration words per second instead of 2.2). Each style also has its own scene types, offered to the model only for that style and drawn as a generic fallback elsewhere: *Launch* an *emblem* (a flat-shaded 3D lozenge spinning into place) and *keys* (3D keycaps pressed on the narration), *Showcase* the *emblem* and a *moment* (a huge time or value that flips on the narration), *Produit* a *diagram* (boxes wired by arrows drawn one by one) and *Slides* a *before / after* comparison. The accent is always the Wavestone green; each repository gets a stable brand surface and music seed, and the model picks layout variants, so sibling platforms do not look alike. Captions are light by default (plain text with a halo) and can be switched to emphasised captions (boxed, current word highlighted). The official Wavestone logo SVGs are used as shipped. The page has three steps, one decision each. *Content*: a single source box that documents, web pages and (optionally) a GitHub repository feed into, the pictures (drop, paste, upload or capture), and a brief column with the purpose, name and link, length, languages, look and rhythm, the rest folded under "More options", and one "Write the script" button. *Edit*: timeline, preview and one inspector with two panes, *Scene* (the selected scene) and *Film* (look, format, rhythm, voice, music, captions: every film-wide setting lives there and nowhere else). *Export*: the videos per language and the project file (save as JSON, open a saved project).
4. **Voice.** `tts` speaks each scene with the voice provider the author set: Azure Speech (the Microsoft neural voices, `fr-FR-RemyMultilingualNeural` first for French) or OpenAI voices, called from the browser with the author's own key (Azure: key and region). The MP3 take is cached per voice, rate and text. Neither provider returns word timings, so cues and captions are timed from the take's length. Without a voice key the film is timed from the text and plays with music and captions only.
5. **Render.** The page is in English. The browser mixes narration, original synthesised music (ducked under the voice) and soft foley with `OfflineAudioContext`, draws every 1920×1080 frame (1080×1920 for the vertical Showcase format) with the same engine as the live preview, encodes H.264 + AAC with WebCodecs and muxes a fast-start MP4. Without an AAC encoder (Safari) the sound is written as 16-bit PCM in a QuickTime `.mov` that Apple devices play; VP9/Opus remains only for browsers without H.264. The finished file's sound is read back and reported. Projects are kept in the author's browser (IndexedDB) and can be exported and imported as JSON.

**AI settings** (the AI status button, top right), as in CrisisMaker: provider and model for the script, provider and key for the voice. Keys are kept in `sessionStorage` (this tab only) and never written to project files; provider, model, server address and region persist in `localStorage`. The "Refresh" button lists the models the key can use.

## Modules

ES modules in `js/videomaker/lib/`, loaded by `js/videomaker/api.js` (the page's API) and `settings-ui.js` (the AI settings dialog); the rest of `js/videomaker/` are classic scripts around `window.VM`.

- `api.js` — `call(action, body)` → `Response`: `config` (languages, voices, AI and voice status, never a key), `analyze` (`{ repo, token? }`), `image` (`{ url, token? }`), `script` (`{ repo, context, languages, images[], brief }` → NDJSON `progress` lines, then `result` or `error`), `tts` (`{ text, voice, rate }` → `{ provider, mimeType, audio (base64), words[] }`). `page`, `screenshot` and `document` answer 501.
- `lib/settings.js` — provider lists, storage of settings and keys.
- `lib/ai.js` — streamed calls to Anthropic (`anthropic-dangerous-direct-browser-access`), OpenAI, OpenRouter and OpenAI-compatible servers, and model lists.
- `lib/writer.js` — the script writer: prompt, one retry with the validation error, progress.
- `lib/script.js` — prompts and the project normaliser (scene types, layouts, theme, languages).
- `lib/github.js` — repository reading and README pictures.
- `lib/voice.js` — Azure Speech and OpenAI voices.
- `lib/json.js` — the JSON object in a model reply.

## Stack and hosting

- **Static site**: `index.html`, `css/`, `js/`, `assets/` at the repository root, vanilla JS and CSS (no npm package at run time). Every path is relative, so it works from a sub-path such as GitHub Pages (`https://<user>.github.io/VideoMaker/`).
- **No server, no database, no Cloudflare**: nothing is deployed besides the files. The only network calls go from the page to the AI provider, the voice provider and `api.github.com` / `raw.githubusercontent.com`, all chosen or triggered by the author.
- **Security**: the Content Security Policy is a `<meta>` tag (`connect-src` allows https and localhost for local AI servers; `media-src blob:` for video clips). Keys never leave the browser except to their own provider.
- **Local use**: `npm start` (a dependency-free static server, `scripts/serve.mjs`).
- **Tests**: Vitest on the ES modules, with mocked `fetch` (no real key, no network): `npm test`. `npm run verify` adds ESLint.
- **CI/CD**: `.github/workflows/ci.yml` runs `npm run verify` on every push and pull request. Publishing is GitHub Pages from `main` (repository root).
